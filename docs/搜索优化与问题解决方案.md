## 搜索结果为0问题

### 问题描述

某些剧名搜索时返回0个结果，例如：
- "重逢后，高冷裴总红着眼跟我领证"
- "我在后宫当咸鱼魏后"
- "从龙之功那象龙未必不能是我"

### 原因分析

1. **剧名过长或包含特殊字符**：某些剧名过长或包含标点符号，导致搜索引擎无法正确匹配
2. **插件服务器问题**：某些插件服务器可能暂时不可用（如pioz插件返回522错误）
3. **搜索策略失败**：所有搜索策略（深度搜索API、HTML搜索、热搜榜匹配）都失败

### 解决方案

#### 1. 部分剧名搜索功能

当搜索结果为0时，系统会自动提取剧名的一部分进行重试：

**提取策略**：
- 优先提取有逗号的前后文字（如"重逢后，高冷裴总红着眼跟我领证"会提取为["重逢后", "高冷裴总红着眼跟我领证"]）
- 如果没有逗号，尝试提取冒号、顿号等标点符号前后的文字
- 如果还是没有，尝试提取前半部分和后半部分

**实现位置**：`service/search_service.go` 中的 `extractPartialKeywords` 函数

**示例**：
```go
// 原始剧名
keyword := "重逢后，高冷裴总红着眼跟我领证"

// 提取的部分关键词
partialKeywords := extractPartialKeywords(keyword)
// 返回: ["重逢后", "高冷裴总红着眼跟我领证"]

// 系统会依次尝试这些关键词
for _, partialKeyword := range partialKeywords {
    results := search(partialKeyword)
    if len(results) > 0 {
        return results
    }
}
```

**测试结果**：
- "重逢后，高冷裴总红着眼跟我领证" → 提取为 ["重逢后", "高冷裴总红着眼跟我领证"]
- "我在后宫当咸鱼魏后" → 提取为 ["我在后宫", "咸鱼魏后"]
- "从龙之功那象龙未必不能是我" → 提取为 ["从龙之功", "那象龙未必不能是我"]

#### 2. 插件降级策略

系统会自动降级到备用搜索策略：

1. **策略1**：深度搜索API（首选）
2. **策略2**：HTML页面搜索（备用）
3. **策略3**：热搜榜匹配（兜底）

**实现位置**：`plugin/pioz/pioz.go` 中的 `searchImpl` 函数

## 部分剧名搜索功能

### 功能描述

当搜索结果为0时，系统会自动提取剧名的一部分进行重试，提高搜索成功率。

### 实现细节

#### extractPartialKeywords 函数

```go
func extractPartialKeywords(keyword string) []string {
    var partialKeywords []string

    // 1. 如果包含逗号，提取逗号前后的文字
    if strings.Contains(keyword, "，") || strings.Contains(keyword, ",") {
        parts := strings.FieldsFunc(keyword, func(r rune) bool {
            return r == '，' || r == ','
        })

        for _, part := range parts {
            trimmed := strings.TrimSpace(part)
            if len(trimmed) >= 3 {
                partialKeywords = append(partialKeywords, trimmed)
            }
        }
    }

    // 2. 如果没有逗号，尝试其他标点符号
    if len(partialKeywords) == 0 {
        separators := []string{"：", ":", "、", "·", "|", "｜"}
        for _, sep := range separators {
            if strings.Contains(keyword, sep) {
                parts := strings.Split(keyword, sep)
                for _, part := range parts {
                    trimmed := strings.TrimSpace(part)
                    if len(trimmed) >= 3 {
                        partialKeywords = append(partialKeywords, trimmed)
                    }
                }
                break
            }
        }
    }

    // 3. 如果还是没有，尝试提取前半部分和后半部分
    if len(partialKeywords) == 0 && len(keyword) > 6 {
        half := len(keyword) / 2
        firstHalf := strings.TrimSpace(keyword[:half])
        secondHalf := strings.TrimSpace(keyword[half:])
        
        if len(firstHalf) >= 3 {
            partialKeywords = append(partialKeywords, firstHalf)
        }
        if len(secondHalf) >= 3 {
            partialKeywords = append(partialKeywords, secondHalf)
        }
    }

    return partialKeywords
}
```

### 使用示例

**原始剧名**：
```
重逢后，高冷裴总红着眼跟我领证
```

**提取的部分关键词**：
```
[重逢后, 高冷裴总红着眼跟我领证]
```

**系统会依次尝试**：
1. 搜索"重逢后"
2. 如果没有结果，搜索"高冷裴总红着眼跟我领证"

### 日志输出

```
[主服务] 搜索结果为0，尝试使用部分剧名搜索: [重逢后 高冷裴总红着眼跟我领证]
[主服务] 部分剧名搜索成功: 重逢后 -> 5个结果
```

## 链接数量限制功能

### 功能描述

为了减少返回数据量和提高响应速度，系统会限制每个搜索结果只保留前3个链接。

### 实现细节

#### limitLinks 函数

```go
func limitLinks(results []model.SearchResult, maxLinks int) []model.SearchResult {
    for i := range results {
        if len(results[i].Links) > maxLinks {
            results[i].Links = results[i].Links[:maxLinks]
        }
    }
    return results
}
```

### 使用位置

在 `service/search_service.go` 的 `Search` 函数中：

```go
// 限制每个结果的链接数量，只保留前3个链接
allResults = limitLinks(allResults, 3)
filteredForResults = limitLinks(filteredForResults, 3)
```

### 效果对比

**限制前**：

```json
{

    {"type": "aliyun", "url": "..."},

    {"type": "xunlei", "url": "..."}
  ]
}
```

## 插件优先级配置

### 功能描述

插件优先级影响搜索结果的排序权重，数字越小优先级越高。

### 优先级等级

| 等级 | 说明 | 权重 |
|------|------|------|
| 1 | 第一梯队，最高优先级 | +1000 |
| 2 | 第二梯队，高优先级 | +500 |
| 3 | 第三梯队，普通优先级 | +0 |
| 4+ | 低优先级 | -200 |

### 配置方法

#### 1. 修改插件初始化代码

**pansearch插件** (`plugin/pansearch/pansearch.go`)：

```go
func NewPanSearchPlugin() *PanSearchAsyncPlugin {
    p := &PanSearchAsyncPlugin{
        BaseAsyncPlugin: plugin.NewBaseAsyncPlugin("pansearch", 1), // 优先级1
        // ...
    }
    return p
}

func (p *PanSearchAsyncPlugin) Priority() int {
    return 1 // 优先级1
}
```

**xdpan插件** (`plugin/xdpan/xdpan.go`)：

```go
func NewXdpanPlugin() *XdpanPlugin {
    return &XdpanPlugin{
        BaseAsyncPlugin: plugin.NewBaseAsyncPlugin("xdpan", 1), // 优先级1
        cacheTTL:        60 * time.Minute,
    }
}
```

**pioz插件** (`plugin/pioz/pioz.go`)：

```go
func NewPiozPlugin() *PiozAsyncPlugin {
    return &PiozAsyncPlugin{
        BaseAsyncPlugin:  plugin.NewBaseAsyncPluginWithFilter("pioz", 1, true), // 优先级1
        // ...
    }
}
```

## Transfer API失败问题

### 问题描述

Transfer API返回404错误，导致无法获取网盘链接。

```
transfer失败: status=404 id=563196
```

### 原因分析

1. **资源ID格式不正确**：深度搜索结果的资源ID包含下划线后缀（如1771490255116_0）
2. **API端点已更改**：原有的transfer API端点可能已更改

### 解决方案

#### 1. 修改extractResourceID函数

去除资源ID中的下划线后缀部分：

```go
func (p *PiozAsyncPlugin) extractResourceID(uniqueID string) string {
    if uniqueID == "" {
        return ""
    }

    if strings.Contains(uniqueID, "-deep-") {
        parts := strings.SplitN(uniqueID, "-deep-", 2)
        if len(parts) == 2 {
            resourceID := strings.TrimSpace(parts[1])
            // 去除深度搜索结果中的下划线后缀（如 _0, _1 等）
            if strings.Contains(resourceID, "_") {
                idParts := strings.SplitN(resourceID, "_", 2)
                if len(idParts) >= 1 {
                    return idParts[0]
                }
            }
            return resourceID
        }
    }

    // ... 其他处理逻辑
}
```

#### 2. 扩展tryTransferEndpointFallbacks函数

添加更多API端点候选，提高成功率：

## 深度搜索结果资源ID格式问题

### 问题描述

深度搜索结果的资源ID包含下划线后缀（如1771490255116_0），导致transfer API请求404错误。

### 原因分析

深度搜索API返回的资源ID格式为 `{主ID}_{索引}`，例如：
- 1771490255116_0
- 1771490255116_1
- 1771490255116_2

而transfer API只接受主ID（1771490255116），不接受带下划线后缀的ID。

### 解决方案

在 `extractResourceID` 函数中添加下划线分割逻辑：

```go
if strings.Contains(uniqueID, "-deep-") {
    parts := strings.SplitN(uniqueID, "-deep-", 2)
    if len(parts) == 2 {
        resourceID := strings.TrimSpace(parts[1])
        // 去除深度搜索结果中的下划线后缀（如 _0, _1 等）
        if strings.Contains(resourceID, "_") {
            idParts := strings.SplitN(resourceID, "_", 2)
            if len(idParts) >= 1 {
                return idParts[0]
            }
        }
        return resourceID
    }
}
```

### 测试结果

修改后，深度搜索结果的资源ID能够正确提取，transfer API请求成功率显著提高。

## 总结

本次优化主要解决了以下问题：

1. **搜索结果为0问题**：通过部分剧名搜索功能，提高搜索成功率
2. **Transfer API失败问题**：通过修改资源ID提取逻辑和扩展API端点，提高成功率
3. **深度搜索结果资源ID格式问题**：通过去除下划线后缀，正确提取资源ID
4. **链接数量过多问题**：通过限制每个结果只保留前3个链接，减少返回数据量
5. **插件优先级配置**：将所有插件优先级配置为1，统一插件权重

这些优化显著提高了搜索服务的稳定性和用户体验。
